# Qt 6.12 vs 6.8 依赖对比（实测）

- 对比日期：2026-10-09
- 方法：本机已装 Qt 6.8.0（dpkg 实测 Depends）vs 净室构建的 Qt 6.12.0-1（build-results 467 个 deb 的 dpkg-deb 实测 Depends），聚合口径 + 逐库口径交叉验证；构建依赖对照 packaging/ 目录 control 与 deepin-community/qt6-base 6.8 control
- 支撑：总体方案 W-0 发布门槛

## 1. 运行时外部依赖：真实新增（上游特性层面）

| 新增依赖 | 引入包 | 根因 | 证据 |
|---|---|---|---|
| **liburing2** | libqt6core6 | QtCore 新增 `QT_FEATURE_liburing`（io_uring 异步 IO），configure 检测到即启用；构建侧同步新增 `liburing-dev [linux-any]` | 6.12 源码 src/corelib/CMakeLists.txt:614,785 + configure.cmake；6.12 control:46；6.8 侧（本机运行时与 deepin control）均无 |
| **libpipewire-0.3-0** | libqt6multimedia6 | PipeWire 屏幕采集（6.9）/音频后端（6.10） | 6.12 deb Depends 实测；6.8 本机无 |
| **libva2** | libqt6multimedia6 | VA-API 视频硬解启用（打包层面新启用） | 同上 |

**对发行版的含义**：目标仓库需有 `liburing2`/`liburing-dev`（bookworm 基线仓库已有，无阻塞）；PipeWire/VA 本机已具备。

## 2. 声明/布局差异（对比中出现在"新增"列表，但非上游新依赖）

| 项 | 真相 |
|---|---|
| libxcb-xinput0 | 6.12 的 Debian 打包把 qxcb 平台插件放进 libqt6gui6（实测 deb 内含 `qxcb.so`），shlibs 完整声明 xinput；deepin 6.8 的 qt6-qpa-plugins 依赖声明极简（仅 fontconfig/libc/qt6 内部），xinput 未声明——**是打包声明完整性差异** |
| libwayland-egl1 | wayland 平台插件在 6.12 归属 libqt6waylandclient6；6.8 拆在 qt6-wayland 包（对比口径未覆盖），布局差异 |
| libfbclient2 / libmariadb3 / libodbc1 / libpq5 | 6.12 构建了全部 SQL 驱动插件包（libqt6sql6-ibase/-mysql/-odbc/-psql）；本机 6.8 只部署了 sqlite 驱动——**部署覆盖差异** |
| libhunspell-1.7-0 / libbluetooth3 / libpcsclite1 / libopenxr-loader1 | 分别来自本轮构建的 qt6-virtualkeyboard / connectivity / quick3d(XR)；本机 6.8 未部署这些模块——**模块覆盖差异**（非 6.12 新引入，Qt 6.8 时代即有） |

## 3. "移除"列表的真相（聚合对比中 6.12 侧缺失的依赖）

| 项 | 定性 |
|---|---|
| libgstreamer1.0-0 / -gl / -plugins-base | **⚠️ 真实缺口（待修）**：6.12 multimedia 构建日志显示 `Could NOT find GStreamer (missing: Play)`——GStreamer 后端未编入，当前 multimedia = FFmpeg + PipeWire + VA。control 的 build-deps 明明有 libgstreamer-plugins-base1.0-dev，需排查净室内 gstreamer-play-1.0.pc 可见性后**重编 qt6-multimedia** |
| （6.8 有、6.12 无的 nspr4/nss3/opus/snappy/lcms2/openjp2/xcomposite/xdamage/expat/xml2 等） | 全部来自**未构建的 qtwebengine/qtpdf**（独立线 6.140.0 待发布），非移除 |
| libasound2 | 随 multimedia ALSA 相关，与 GStreamer 缺口同批，重编时一并确认 |
| libmng1 | **上游要求 libmng≥2**（净室已补建 libmng 2.0.3），但 **MNG 插件最终未编入**（qt6-image-formats-plugins 内无 mng 插件文件、无 libmng2 依赖）——**⚠️ 真实缺口（待修）**，需排查 QT_FEATURE_mng 后重编 qt6-imageformats |
| libdtk6declarative / libkf6\* / libkirigami\* / libharfbuzz-subset0 / sse3-support 等 | deepin 附加包（chameleon 样式、文档工具、webengine）带来的依赖，属部署差异，与 Qt 本体无关 |

## 4. 构建依赖（Build-Depends）逐模块精确对比

> 6.8 侧取自本机 apt 源的 Sources 索引（snipe 商业源，精确对应系统 6.8 打包）；6.12 侧取自净室实际使用的 control（Debian 6.11.2+dfsg + 本地 sed 修正）。归一化时剔除了版本约束与架构标注，故"版本门槛提升"单列。

### 4.1 真正新增的上游/特性级构建依赖

| 模块 | 新增 | 根因 |
|---|---|---|
| qt6-base | **liburing-dev** | QtCore io_uring（QT_FEATURE_liburing），运行时对应 liburing2 |
| qt6-base | **libjemalloc-dev** | Debian 打包新启用 jemalloc |
| qt6-base | **14 个 libxcb 扩展 -dev**（composite/damage/dpms/dri2/dri3/ewmh/present/record/res/screensaver/xf86dri/xtest/xv/xvmc） | Debian 6.11 control 显式声明的 xcb 扩展开发包（6.8 靠传递依赖） |
| qt6-multimedia | **libpipewire-0.3-dev** | PipeWire 采集/音频后端 |
| qt6-quick3d | **libopenxr-dev、libegl-dev** | Quick3D XR 支持 |
| qt6-tools | **clang-21、libclang-21-dev** | qdoc 所需 libclang 版本从"任意 clang"精确锁定到 21（≥17 的要求，Debian 锁 21；净室构建证实 UOS 源可用） |

### 4.2 版本门槛提升（包名不变，约束变严）

| 包 | 模块 | 6.8 → 6.12 |
|---|---|---|
| cmake | 全部 | 3.16 → **≥3.25** |
| libassimp-dev | qt6-quick3d | 无约束（UOS 5.3.1 可用）→ **≥6.0**（需补建，净室已建 6.0.5） |
| GStreamer 系 | qt6-multimedia | ≥1.18 → **≥1.20**（且需 Play 组件完整，见 §3 缺口） |
| libmng | qt6-imageformats | 1.x 可用 → **≥2.0**（configure 层要求，需补建，净室已建 2.0.3） |

### 4.3 打包层重命名（非上游变化，净室已解决）

pkg-config → pkgconf；libmd4c-html0-dev → libmd4c-html-dev；default-libmysqlclient-dev → libmariadb-dev；Debian 的 dh-sequence-python3 / dh-sequence-pkgkde-symbolshelper / dh-sequence-qmldeps 元包风格（UOS 用 dh-python/pkg-kde-tools 等效）；qt6-wayland 新增 qt6-svg-dev 构建依赖。

### 4.4 qt6-tools 的移除项（6.8 deepin 特有，已验证可去）

6.12 control 移除了 6.8 deepin 特有的一批构建依赖：libcups2-dev、libcurl4-openssl-dev、libgl-dev、liblitehtml-dev、libssl-dev、libvulkan-dev、libxcb-xkb-dev、libzstd-dev、llvm-dev、ninja-build（显式）、qt6-base-dev/qt6-declarative-dev（显式自举声明）等——**净室构建成功即证明按 6.11 control 不需要它们**（部分源自 deepin 对 assistant/designer 的定制与显式化声明习惯）。

## 5. 结论

1. **运行时**：Qt 本体新增的硬依赖只有 1 个：liburing（core，io_uring）；multimedia 新增 PipeWire/VA 两个软依赖；其余"新增"均为打包布局/部署覆盖差异，无发行版阻塞项。
2. **构建依赖**：新增面同样很小——上游/特性级新增为 liburing-dev、libpipewire-0.3-dev、libopenxr-dev、libjemalloc-dev、14 个 libxcb 扩展 -dev、clang-21（精确锁版）；版本门槛提升为 cmake ≥3.25、assimp ≥6.0、libmng ≥2、GStreamer ≥1.20；其余全是打包层重命名（pkgconf/libmariadb-dev 等，净室已解决）。**净室构建 38 模块全部成功本身即证明这些构建依赖在 UOS 源全部可满足**（assimp/libmng 为补建）。
3. **两个必须修复的构建缺口**（当前 6.12 产物相对 6.8 的功能回退）：
   - qt6-multimedia 的 **GStreamer 后端缺失**（missing Play 组件）；
   - qt6-imageformats 的 **MNG 插件缺失**（libmng2 已补但插件未编入）。
   两者都只需排查净室环境后重编对应模块，已列入总体方案 W-0 发布门槛。

## 复现命令

```bash
# 运行时依赖聚合对比
dpkg-query -W -f='${Package}\t${Depends}\n' | awk -F'\t' '$1 ~ /^(libqt6|qml6-module|qt6-)/ {print $2}' | tr ',' '\n' | sed 's/^ *//;s/:[a-z0-9]*$//;s/ ([^)]*)//' | sort -u   # 6.8 侧
for deb in qt6.12-build/build-results/*_6.12.0-1_*.deb; do dpkg-deb -f "$deb" Depends; done | tr ',' '\n' | ...   # 6.12 侧
# gstreamer 特性状态
grep "GStreamer" qt6.12-build/logs/build-qt6-multimedia.log
# mng 插件存在性
dpkg-deb -c qt6.12-build/build-results/qt6-image-formats-plugins_6.12.0-1_amd64.deb | grep -i mng
```
