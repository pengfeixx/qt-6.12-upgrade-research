# 阶段二补充：linuxdeepin 组织（GitHub）源码仓库扫描

- 扫描日期：2026-10-08
- 工具：`gh` CLI（已认证账号 pengfeixx）
- 用途：补齐本机二进制反向依赖看不到的**源码级构建依赖面**（debian/control 的 Build-Depends），找出本机未安装的其他受影响应用
- 支撑：《阶段2-受影响应用与场景分析.md》§2.3

## 1. 扫描方法与口径

1. `gh repo list linuxdeepin --limit 300` 拉取组织全部仓库元数据：**265 个仓库**（171 个 2025 年后仍有 push，137 个 2026 年后活跃）。
2. GitHub 代码搜索 API（`gh api search/code`）逐类查询 `debian/control` 中的 Qt6 构建依赖。
   - ⚠️ 踩坑记录：`path:debian/control` 限定词在当前代码搜索中匹配不到任何结果（返回 0），改用 `filename:control` 正常工作。复现查询形如：`gh api -X GET search/code -f q='org:linuxdeepin filename:control qt6-base-private-dev'`
3. 仓库名与本机包名做映射后比对（映射表见 §3），得出"本机没有的"新增影响面。

## 5. 关键洞察

1. **源码级私有头面与二进制级互相印证**：linuxdeepin 组织内 35 个仓库用 `qt6-base-private-dev`，与二进制扫描的 68 个私有 ABI 消费者吻合——差额（KF6 系列库、fcitx5、python3-pyqt6、qtcreator、kio6 等）的上游源码不在 linuxdeepin 组织（KDE/Qt/Riverbank 等第三方打包），**升级时这部分跟随上游发版节奏，不由 deepin 控制**。
2. **deepin-kwin 与 kwin 双仓库并存**：linuxdeepin 组织有 deepin-kwin（fork），本机安装的是 KDE 上游版本号的 kwin 4:6.1.x——升级方案要明确走哪条线（deepin fork or 上游 kwin），两条线的 Qt 适配节奏不同。
3. **分支仓库**：存在 `dde-session-shell-snipe` 这类产品线分支仓库（snipe = V25 专业版），说明同一组件有多分支维护，Qt 6.12 适配需要覆盖所有活跃分支而不是仅 master。
4. **deepin-skills / dtkai / rofd** 等新组件持续进入 Qt 生态，影响面仍在扩大。
